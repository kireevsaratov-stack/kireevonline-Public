# Решения

Что решили, когда и почему. Новое — сверху. Подробности — в истории рабочего (приватного) репозитория и `docs/reviews/`.

## Октябрь 2026

**11.10 — Публичная копия кода** (`kireevonline-Public`, собирает `../showcase/make_public.py`): одна версия без истории, без базы, фото и личного; демо-данные для пустой копии — `manage.py demo_data`. Подпись «(тестовая)» у галочки скрытия и подсказка про бэкап на странице загрузки убраны (отметку бэкапа на сервер никто не пишет — подсказка была всегда неверной).

**09.10 — Перекрёстная проверка моделями, круг 2** (`docs/reviews/2026-10-09-cross-review-2.md`): прошлые исправления в основном
подтверждены; новые находки — про обрывы посреди операций. Исправлено с тестами: прерванный откат оставляет
отметку и откатывается назад следующим запуском; доделка прерванной выкладки берёт снимки «до» (база и библиотеки);
откат через шаги с текстами 0009–0013 запрещён; архив проверяет, что база подходит к коду; у фото номер загрузки
(миграция 0015) — повтор после обрыва не создаёт дубль и не «застревает»; неудачная запись стирает свои файлы;
устаревшая копия альбома не возвращает фото в старый раздел; загрузчик останавливается, если вход истёк, и держит
альбом на всю партию; в панели Django нет загрузки файлов фото (Роман ею не пользуется); мелочи — сетка после
удаления, надписи про корзину, клавиатура, журнал действий. Отложено: сверка бэкапа по содержимому.
**Бэкапы (решение Романа):** снимок перед каждой выкладкой + архив раз в месяц и по команде; ежедневный — не нужен.

**09.10 — Pillow не новее 12.2.0.** Выкладка с Pillow 12.3.0 не встала: для него нет сборок под старый Linux
хостинга (glibc 2.17), собрать на месте сервер не может. Выкладка сама вернула код; библиотеки не менялись, сайт
не переключался. Последний шаг возврата споткнулся о снимок библиотек (`pip freeze` пишет setuptools хостинга
ссылкой на файл) — снимок теперь `pip list --format=freeze`. Выкладка теперь заранее проверяет, что для всех
библиотек есть сборки под сервер (и тест на GitHub). Уязвимость разборщика EPS из 12.3.0 закрыта кодом:
загрузка разбирает только JPEG/PNG/WebP (тест, что разборщик EPS не вызывается). Вопрос к хостингу на будущее —
переезд на более новую систему.

**09.10 — Оповещения GitHub об уязвимостях Pillow 12.2.0 (13 штук) — риск принят, путь закрыт кодом.** Pillow на сайте
только открывает JPEG/PNG/WebP, поворачивает, ужимает и сохраняет JPEG. Ни одна из 13 не достижима: JPEG2000, McIdas,
GD, EPS, PDF — форматы не разбираются; шрифты BDF/PCF/FontFile, RankFilter, ImageCms, сохранение в TGA, Windows-просмотр —
не используются; paste/crop с чужими координатами не вызываются. Дополнительно каждая сторона картинки — 1…30 000 px
(площадь 120 Мп уже была). В GitHub оповещения закрыты с причиной «уязвимый код не используется». Пересмотреть при
переезде хостинга на новый Linux — тогда обновить Pillow.

**09.10 — Перекрёстная проверка моделями (GPT и Claude), круг 1** (`docs/reviews/2026-10-09-cross-review-1.md`): 16 находок. Исправлено всё, что ломает
работу или данные, каждая находка закрыта тестом, который падал на прежнем коде:
библиотеки с исправлениями безопасности; загрузка — только JPEG/PNG/WebP до разбора, полный разбор, битое — отказ,
части с фиксированными параметрами, сборка целиком и один раз; раздел фото = раздел альбома, единое правило
видимости и обложек; файлы стираются после записи в базу, уборка не трогает свежие; номера и названия без
ответов 500; пауза входа на файлах с блокировкой; выкладка доделывает прерванную, сорвавшийся откат возвращает базу
из снимка, база из снимка — только со своей версией, стили при новых библиотеках, версия на всех страницах;
архив согласован (код версии сервера + все файлы базы, проверка собранного). Документы приведены к тому, что
код действительно гарантирует. **«Скрыт» = черновик, не секрет**: файлы скрытых фото по точному адресу доступны
(закрытая выдача — в бэклоге). Не делаем (лишнее для одного владельца): права редакторов, ускорение запросов,
демо-данные; общий лимит входа может закрыть вход и владельцу — принято. Проверку библиотек на уязвимости —
пересмотреть: включить оповещения GitHub.

**08.10 — Уборка проекта.** Понятные имена вместо «категория/подкатегория»: модели `Section`/`Album`, адреса
`/section/…`, `/album/…`, `/shuffle/` (старые `/photos/…` — постоянные перенаправления; `/photos/` по-прежнему
отдаёт главную: когда-то «/» навсегда вёл на `/photos/`, обратный редирект дал бы браузерам петлю).
`views/` по темам, стили и скрипты — файлами, `tools/` → `deploy/`, тесты по темам, ruff, хук перед версией,
автотесты на GitHub. Ориентир — общепринятое для проекта такого размера, без «командной» тяжести
(Docker, PostgreSQL, отдельный тестовый сервер не нужны).

**08.10 — Выкладка остаётся с Mac**, а не с GitHub: последнее слово за владельцем, ключ от сервера не хранится
на GitHub, отправка версии на GitHub ничего не выкладывает. Вместо «тесты на GitHub зелёные» выкладка сама
прогоняет автотесты на выкладываемой версии (проверить статус GitHub с Mac можно только с токеном).

**08.10 — Адреса панелей:** `/admin/` — своя панель со своей страницей входа (кто заглянет — увидит, что панель
сделана сознательно), `/admindjango/` — панель Django. Вход общий.

**08.10 — Защита.** Сделано: CSP (только свои скрипты, ничего с чужих серверов), пауза после неверных паролей,
журнал действий, security.txt, HSTS на год, шрифт со своего сервера («максимально российский сервер»).
Не делаем (проект мелкий и некоммерческий, красть нечего — всё в бэкапах, личных данных нет): код из приложения
при входе, свой адрес входа, ключ выкладки с паролем, проверку библиотек на уязвимости.

**08.10 — Ничего, что собирает данные посетителей:** ни Метрики, ни своей статистики, ни гостевого входа —
обязанности по 152-ФЗ без пользы для сайта. Сайт остаётся продуктом; рассказ о технике — вне сайта.

**08.10 — На сайте нет следов AI.** Работа с AI видна только в репозитории (`CLAUDE.md`, `.claude/`).

**08.10 — Поиск по фото словами и подписи для незрячих — отложены** (проба на 12 фото — в заметках).

**03.10 — Своя панель управления вместо админки Django** для ежедневной работы: порядок перетаскиванием,
скрытие, переименование, создание (новое — сразу скрытое), удаление только пустого, тексты с живым видом,
перенос фото. Админ видит публичный сайт как гость; скрытое — только в панели.

**02.10 — «Барабан»** (название Романа; «Наугад» отвергнут): все видимые фото вперемешку, кнопка — однорукий
бандит. У каждого барабана свои картинки; рычаг опускается, круглые детали не сплющивать. Превью
прорисовываются сверху вниз по мере загрузки — без плавного проявления.

**01–02.10 — Описания альбомов.** Уровни: место + один месяц, «Коротко», записки по «+», «Снято на» видно всегда.
Тексты — из ответов Романа его словами; его текст — канон, правки сверх опечаток — нумерованными предложениями.
Репортаж и Прогулки — короткие подписи без записок. Тексты Роман вставляет сам через панель.

**01.10 — Безопасные настройки по умолчанию, проверка загрузок,** повторное сохранение фото не пережимает.

**01.10 — Выкладка терпит VPN:** первая попытка 4ef3f24 откатилась ложно (запросы через VPN висят 16–40 с) —
проверка ждёт до 45 с на страницу и до 6 минут в целом. VPN у Романа не выключать.
