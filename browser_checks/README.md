# Проверки в настоящем браузере

Скрипты запускают Chrome без окна и проверяют сайт так, как его видит человек: анимации, загрузку
картинок, перетаскивание в панели, вид на телефоне. Нужны только Google Chrome и Node 24 (fetch и WebSocket
встроены) — никаких библиотек. Поэтому не Playwright: ему нужны npm-пакеты и свой браузер, а здесь ставить
нечего и обновлять нечего. Профиль Романа не трогается: у каждого запуска свой временный профиль Chrome во
временной папке системы, после запуска он стирается.

## Одной командой

Сначала запустить копию сайта на Mac (`http://localhost:8100`, база `../db.sqlite3`, фото из `../../backups/media`;
скил `browser-check`, шаг 1), затем из этой папки:

```bash
node run_all.mjs            # все 8 проверок, итог «8 из 8 прошли»; что-то не так — код выхода 1
node run_all.mjs --no-admin # без панели управления и загрузки (без временного админа)
```

`run_all.mjs` запускает проверки по очереди, каждую отдельным процессом со своим пределом времени. Для панели
управления сам создаёт временного админа `ui-check` ТОЛЬКО в локальной базе (случайный пароль — в файле
`kireevonline-ui-check-pw.txt` во временной папке системы) и в конце в любом случае удаляет и его, и файл.
Сессию из `manage.py shell` локальный сервер не примет (у него случайный SECRET_KEY) — скрипты входят через форму.

Каждая проверка сама сообщает итог: строки «✓ …» / «✗ …», в конце «ПРОШЛО» или «НЕ ПРОШЛО (n из m)» и код
выхода 0 / 1. Замеры для человека печатаются отступом и на итог не влияют. Любую можно запустить и отдельно:
`node <скрипт>`.

| Скрипт | Что проверяет |
|---|---|
| `spin_check.mjs [ширина высота прогонов]` | «Барабан»: барабаны трогаются сразу и по очереди встают точно на кадр (±1 px), кнопка снова свободна, сетка собрана и не прыгает после появления, в окошках — первые 3 кадра сетки, страница не зависает дольше 400 мс |
| `reel_unique_check.mjs [адрес] [пауза мс]` | телефон, медленная сеть: у каждого барабана свои картинки, ни одна не в двух сразу, без повторов подряд, следующее вращение берёт сначала новые картинки, битых превью нет |
| `lever_check.mjs [shots]` | рычаг «Барабана»: шарик круглый на всём ходу, двигается только вниз и возвращается, стержень только укорачивается |
| `album_check.mjs [адрес] [phone]` | альбом: сначала 40 превью (и не больше 40 запросов), прокрутка догружает, битых нет, кадр из догруженных открывается в просмотре; на телефоне полный экран не включается |
| `nav_check.mjs [shots]` | шапка на ширинах 412–1440 у гостя и админа: пункты не переносятся, меню влезает или свёрнуто в гамбургер; на узких — гамбургер, и он раскрывает меню |
| `keyboard_check.mjs [адрес]` | фото и меню доступны клавишей Tab, Enter открывает фото, Esc закрывает |
| `manage_e2e.mjs [ширина] [shots]` | панель `/admin/`: вход через свою страницу, перетаскивание мышью и пальцем, скрыть, переименовать, создать и удалить, тексты с живым видом, перенос фото — всё с возвратом как было и сверкой базы в конце (нужен временный админ) |
| `upload_check.mjs` | загрузка через страницу панели: временный скрытый альбом с «неудобным» названием, картинка 2600×1800 → в базе, ужата до 1920, превью; при истёкшем входе загрузка останавливается; всё за собой убирает (нужен временный админ) |
| `view_shot.mjs адрес ширина высота файл [phone]` | снимок первого экрана (не проверка) |
| `page_shot.mjs адрес ширина файл [phone]` | снимок альбома или «Обо мне» с раскрытыми записками (не проверка) |

`shots` — ещё и снимки для глаз (`lever/`, `nav_*.png`, `manage_*.png`, `move_*.png`). Снимки в git не попадают.
Плотность точек у снимков — переменная `SCALE` (по умолчанию 2); при ширине 1440 новый Chrome на ×2 зависает —
тогда `SCALE=1`.

## Общее — `lib.mjs`

Всё повторяющееся — здесь, скрипты только проверяют:
- `openChrome({ width, height, scale, mobile, extraArgs })` — Chrome без окна со свободным портом и своим
  временным профилем; возвращает `js(выражение)` (значение со страницы; ошибка на странице — исключение),
  `navigate(адрес, пауза)`, `screenshot(файл, { clip })`, `setViewport`, `send` / `on` для протокола Chrome, `close()`;
- `main('название', async t => { … t.ok(условие, 'что проверено', подробности) … })` — итог «прошло / не прошло»,
  код выхода, предел времени (120 с по умолчанию, переменная `TIMEOUT` в секундах): зависший Chrome не держит
  скрипт вечно, при любом выходе Chrome закрывается и профиль стирается;
- `login(page)` — вход временным админом через форму, `sql(запрос)` — чтение локальной базы.
