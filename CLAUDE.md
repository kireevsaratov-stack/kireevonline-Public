# kireevonline.ru — правила для Claude

Личная фотогалерея Романа Киреева (Django 5.2, SQLite). Самый важный проект Романа.
Роман не программист: по-русски, на «ты», просто и без жаргона; решения — его, предлагать с рекомендацией.
Устройство — `docs/architecture.md`, решения и их причины — `docs/decisions.md`, отложенное — `docs/backlog.md`.

## Сервер меняет только Роман

- Claude **никогда** не выкладывает, не откатывает, не правит файлы и базу на сервере, не загружает и не удаляет
  фото, не меняет настройки хостинга. Готовит изменение и даёт Роману одну команду блоком `bash` (скил `release`).
- Читать сервер — **только** `python3 deploy/status.py` и `python3 deploy/backup.py` (ключ
  `~/.ssh/kireevonline_readonly` → шлюз `ro-gate.py`, запись по нему запрещает сам сервер). Прямой ssh/scp/rsync — нет.
- Это держит хук `~/.claude/hooks/kireevonline-guard.sh` (вне проекта; проверка — `deploy/tests/test_guard.py`).
  Не обходить и не ослаблять без явной просьбы Романа. Ложное срабатывание (имя скрипта выкладки в тексте
  команды, например после «(») — переформулировать или править файл через Edit.
- Разовое исключение — только по явному «да» Романа в чате на конкретное действие: файл
  `~/.claude/hooks/kireevonline-allow-once` со строкой `<срок unix> <скрипт>…`, срок ≤ 30 минут, удалить сразу после.
  «Бэкап» (копия на Mac) и «выкладка» (код на сайт) — разные вещи, не смешивать в одном вопросе.
- Живой сайт — только как посетитель: GET без отправки данных; версия кода на сайте — заголовок `X-Site-Version`.
- Секреты не выводить: `git remote -v`, конфиги, `site.wsgi` — только с маскировкой.

## Как вносить изменения

1. Рабочая ветка (не `main`). Перед заметными изменениями — `python3 deploy/backup.py`.
2. Правка → `../.venv/bin/python manage.py test photos` → копия сайта на Mac (скил `browser-check`) → снимки Роману.
   Локально нужен `DJANGO_DEBUG=True` (без него сайт «боевой»: https, защищённые cookie).
3. Хук `.githooks/pre-commit` (включён: `git config core.hooksPath .githooks`) перед каждой версией прогоняет
   ruff и тесты. На GitHub — `.github/workflows/tests.yml`.
4. Роман одобрил → скил `release`. Миграции — только обратимые. Отдельно предупреждать о миграциях и `requirements.txt`.
5. Коммиты — с noreply-почтой GitHub, в конце строка `Co-Authored-By`.

Обновить базу на Mac с сайта: `python3 deploy/backup.py --db-only`, свежий файл из `../backups/db/` — в
`gallery/db.sqlite3`, старую базу — в `../_архив/` (не удалять). Тексты альбомов Роман правит прямо на сайте,
поэтому локальная база отстаёт.

## Скилы (`.claude/skills/`)

| Скил | Когда |
|---|---|
| `release` | изменения готовы и одобрены — проверки, `main` на GitHub, команда Роману, проверка сайта после |
| `browser-check` | проверка в браузере на копии сайта, временный админ только в локальной базе, снимки |
| `album-notes` | записки к альбомам: все кадры, данные из оригиналов, вопросы, текст словами Романа |
| `backup` | полный архив для облака с проверкой распаковкой |

## Подводные камни

- Шаблоны: каждый `<script>` — с `nonce="{{ request.csp_nonce }}"`, обработчики только через `addEventListener`
  (CSP; тест это ловит). Ничего не подключать с чужих серверов.
- Админ видит публичные страницы как гость; скрытое — только в панели `/admin/` и по прямой ссылке. Служебные
  списки («Перенести в альбом…») — полные, через `admin_sections`. На странице «Альбомы» скрытая строка —
  класс `mg-off`, не `is-hidden` (тот на сайте прячет кадры).
- Фото — только через `Photo.from_upload` (проверка и сжатие в `photos/media.py`, ошибка — отказ); «что видит
  гость» — только `Photo.objects.visible()`; раздел фото берётся из альбома в `Photo.save`. «Скрыт» = черновик:
  файл по точному адресу открывается. Номера из запросов — `photos/views/params.py`.
- `/photos/` отдаёт главную без редиректа — не менять (петля у браузеров со старым 301).
- Хостинг перезапускает сайт с опозданием до минут; через VPN Романа запросы висят 16–40 с — выкладка это терпит.
- У «Питера 2024» на сервере id 40, в старых локальных базах был 41 — искать альбомы по имени, не по номеру.
- Сайт стирает данные камеры при загрузке; оригиналы — `~/Фото/<событие>/`, читать только дату, камеру, объектив.
